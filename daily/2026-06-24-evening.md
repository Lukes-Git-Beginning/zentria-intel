#### HN: "The Coming Loop" — Armin Ronacher über Harness-Loop-Architektur (n_sources:1, score:0.47, HN:349)

**Quelle:** [lucumr.pocoo.org — The Coming Loop](https://lucumr.pocoo.org/2026/6/23/the-coming-loop/) (2026-06-23, HN 349 Punkte)

**Was passiert:**
Armin Ronacher (Autor von Flask, Jinja2, Ruff — engineering credibility: sehr hoch) unterscheidet zwei Loop-Patterns in Agentic Systems:
- **Agent Loop**: Modell ruft Tools auf, integriert Ergebnisse, iteriert intern bis Completion-Deklaration
- **Harness Loop**: Externe Supervision entscheidet ob Arbeit fertig ist, re-queued Tasks, modifiziert Kontext über mehrere Iterationen

Ronacher's zentrale Warnung: Harness-Loops produzieren Code der "einem Organismus gleicht" — nützlich aber nicht mehr lesbar ohne AI-Assistance. Teams mergen Code den sie nicht vollständig erklären können. Cognitive dependency auf Maschinen für Code-Verständnis.

Kernthese: **"Niemand kann sich wirklich opt-out nehmen"** — Sicherheitsforschern und Angreifern steht die gleiche Harness-Loop-Technologie zur Verfügung. Wer sie nicht nutzt, verliert.

**Was bedeutet das für Cosmi?**
Ronacher's Argument trifft Cosmi an zwei Stellen:

1. **Cosmi-AI-Feature-Entwicklung:** Falls Cosmi AI-Coding-Agents für interne Entwicklung einsetzt (Claude Code ist bereits im Stack, wie die Routine-Infrastruktur zeigt): Harness-Loops sind mächtig, aber sie produzieren Code der ohne Maschinen-Hilfe schwerer zu reviewen ist. Cosmi braucht explizite **"Human-Legibility-Standard"** für AI-generierten Code — nicht weil AI-Code schlecht ist, sondern weil der Review-Prozess sonst wegbricht.
2. **Cosmi-Produkt für Kunden:** Wenn Cosmi AI-Agents für Kunden-Workflows baut (Helpdesk-Triage, CRM-Automation), ist die Frage: wessen Loop-Architektur?
