**Was passiert:**

Twenty v2.45.0 wurde am 05.10.2026 released. 68 PRs, 4 Releases an einem Tag (v2.44.0 → v2.44.1 → v2.45.0 im Stundentakt). Folgende Kernfeatures wurden ausgeliefert:

**Record-Level Sharing (5-Part-Implementierung):**
1. `PR #27045` — Access Restrictions: Records offener Objekte sind jetzt standardmäßig korrekt eingeschränkt (kein öffentlicher Default-Read mehr)
2. `PR #27054` — Role-Beyond Sharing: Records können über die Empfänger-Rolle hinaus geteilt werden — flexibles Permission-Modell
3. `PR #27057` — UI Integration: Sharing-Controls auf jedem Objekt, Detail-Panels und Objekt-Settings
4. `PR #27058` — "All records" Permission + Ownership Transfer
5. `PR #27068` — Row-Level Access Policy: Einheitliche Policy für Queries, Events und Writes — vollständige RLS-Integration

**SDK Application Workflows (PR #26662):**
Proof-of-Concept: Entwickler können Application-Workflows jetzt via SDK definieren, nicht nur via UI. Application Workflows laufen unter den Permissions der owning Application (PR #27055) — nicht des Users. Email- und Calendar-Steps aus Application-Workflows ausgeschlossen (PR #27072). Core-Workflow-Versionen sind Command-Menu-Items.

**2FA Hardening (PR #26583):**
Verbesserte Validierung gegen Impersonation-Angriffe und OTP-Guessing. Dependency-Updates: axios 1.20.0, ip-address 10.7.2, piscina 4.9.4.

**Breaking Changes:**
- 2.44-Compatibility-Layer entfernt — Update aus Zwischenversionen erforderlich
- `authContext` deprecated → `RawAuthContext` (Typ-Sicherheit)
- Feature-Flags `IS_UNIQUE_INDEXES_ENABLED` + `IS_JUNCTION_RELATIONS_ENABLED` removed
- Legacy DB-Tabellen `campaignDelivery` + `messageSuppression` entfernt

**Was bedeutet das für Cosmi?**

Record-Level Sharing ist eine der am häufigsten genannten Enterprise-Anforderungen im CRM-Markt — granulare Zugriffssteuerung auf Datensatz-Ebene, nicht nur auf Objekt-Ebene. Twenty hat dies in einer einzigen Release-Welle als vollständige 5-PR-RLS-Implementierung mit UI-Integration ausgeliefert. Cosmi-CRM-Core hat kein Äquivalent dokumentiert. Der SDK-Workflow-PoC ist ebenfalls strategisch: Twenty baut eine Developer-Platform, die Eigenentwicklungen direkt in den CRM-Kern einbettet — direkter Angriff auf Cosmis "alles im Kern" vs. Twenty's "Kern + extendierbar." Die Ship-Rate (68 PRs in einer Version, 4 Releases in einem Tag) bestätigt W33-Keeper `twenty-sprint-kadenz-47h-major-releases-w33`: Feature-Parity als Cosmi-Strategie ist strukturell nicht haltbar. Die W33-Architekturentscheidung (Fork/Own/Non-Parity) muss jetzt eskaliert werden — Record-Level Sharing zeigt, dass Twenty in Enterprise-Segmente vorstößt, die Cosmi bisher für sich beansprucht hat. ## Was widerspricht Cosmi-Strategie heute?

### 1. Self-hosted + Anthropic-API ≠ Zero-Knowledge

Der heutige Anthropic-Polizei-Fall ist für Cosmi ein zweischneidiges Schwert. Cosmi vermarktet "self-hosted, DSGVO-by-design" — aber wenn AI-Features über Anthropic-API laufen, verlassen Nutzerdaten die Cosmi-Infrastruktur und landen auf US-Servern. Anthropic kann diese Daten in definierten Szenarien an Behörden melden. Cosmi kann aktuell nicht ehrlich sagen "eure Daten verlassen euren Server nie" wenn der AI-Backend Anthropic ist. **Lösung ist bekannt und offen (W25-P0): Multi-Provider-Router + Mistral EU + On-Premise-Adapter** — aber bis dieser Router produktiv ist, hat Cosmi eine kommunikative Lücke zwischen Marketing-Versprechen und technischer Realität. Das muss intern anerkannt und im Sales-Training transparent kommuniziert werden, bevor ein Wettbewerber es öffentlich exponiert.

### 2. Twenty v2.45.0 hat Record-Level Sharing — Cosmi nicht

Twenty hat heute mit 68 PRs in einem Release das Permissions-Modell fundamentaler weiterentwickelt als Cosmi im gleichen Zeitraum. Record-Level Sharing ist eine Anforderung, die Cosmi-Prospects ab mittlerer Größe (20+ User, mehrere Teams) stellen werden. Die W33-Architekturentscheidung (Fork/Own/Non-Parity) liegt seit 5+ Wochen unentschieden. Jede weitere Woche ohne Entscheidung ist eine Woche, in der Twenty seinen technischen Vorsprung weiter ausbaut — und eine Woche, in der Cosmi-Sales-Teams keine ehrliche Antwort auf "Wie funktioniert Record-Level Access?" geben können.

Langdock musste explizit von Delaware nach Deutschland umziehen um seinen Sovereignty-Bonus zu monetarisieren.
