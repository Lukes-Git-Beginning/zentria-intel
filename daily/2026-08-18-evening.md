#### AI-Generated Copilot Autofix → Snowflake Jira Compromise (n_sources:1, score:7.5)

**Quellen:**
- [HackerNews #49331423](https://news.ycombinator.com/item?id=49331423) (Wiz.io Sicherheitsbericht, HN Score 330)

**Was passiert:**
GitHub Copilot Autofix hat eine verwundbare Shell-Interpolation in Snowflakes GitHub Actions CI/CD-Workflow eingeführt: `` TITLE=$(echo '${{ github.event.issue.title }}' | sed ...) `` ermöglicht beliebige Command Injection via Single-Quote-Character im Issue-Titel. Ein fehlerhafter Conditional Check erlaubte zusätzlich alle GitHub-User. Die Kombination ermöglichte die Kompromittierung von Snowflakes Jira-Instanz. Angriffsszenario: Angreifer erstellt Issue mit präpariertem Titel → CI/CD führt beliebige Commands aus.

**Was bedeutet das für Cosmi?**
Dies ist der bisher prominenteste dokumentierte Fall, in dem AI-generierter Code direkt eine Sicherheitskompromittierung verursacht hat. Cosmi entwickelt AI-Features mit Claude Code und plant AI-gestützte Code-Reviews. Zwei direkte Maßnahmen: (1) **CI/CD-Audit**: Alle GitHub Actions Workflows auf Shell-Interpolation von externen Inputs prüfen — insbesondere `github.event.issue.title`, `github.event.pull_request.title`, User-Inputs in YAML-Steps. Tool-Empfehlung aus HN-Community: `zizmor` und `actionlint`. (2) **Policy für AI-generierten CI/CD-Code**: AI-Tools (Copilot Autofix, Claude Code) dürfen keinen CI/CD-YAML ohne Human-Review-Gate committen. Dies ist keine Capabilities-Kritik an AI, sondern Architekturentscheidung: CI/CD-Pipelines haben erhöhten Blast-Radius. Module-Pfad: `backend/internal/ci/security-review-policy.md`.

#### EU AI Act: Artikel-50-Transparenzpflichten seit 2. August in Kraft (n_sources:3, score:7.8)

**Quellen:**
- [Cooley LLP Insight](https://www.cooley.com/news/insight/2026/2026-08-03-eu-ai-act-transparency-obligations-take-effect-2-august-2026) (Rechtliche Analyse)
- websearch aljazeera (Newsmeldung)
- HN-Reaktionen (Community)

**Was passiert:**
Artikel-50-Pflichten des EU-AI-Acts sind seit **2. August 2026** in Kraft: (1) Offenlegungspflicht bei interaktiven KI-Systemen — Nutzer müssen wissen, dass sie mit einem KI-System interagieren (Chatbots etc.). (2) Maschinenlesbare Markierungen + Erkennungsmechanismen bei KI-generierten Inhalten (Audio, Bild, Video, Text — SynthID-Ansatz). (3) Hinweispflicht bei Emotion-Recognition und Biometrie. (4) Deepfake-Kennzeichnungspflicht bei öffentlichkeitsrelevantem Content. **Bußgelder**: bis 15 Mio. EUR oder 3% des weltweiten Jahresumsatzes. **Übergangsfrist**: Generative KI-Systeme die bereits im Einsatz sind, haben bis **2. Dezember 2026** für technische Markierungsanforderungen. Freiwilliger Code of Practice der AI Office verfügbar; Unterzeichner erhalten Konformitätsvermutung.

**Was bedeutet das für Cosmi?**
Cosmi plant AI-Features in Helpdesk, CRM und Dialer. Artikel 50 greift ab dem Moment, in dem Cosmi-Nutzer mit einem AI-System interagieren (Chatbot-Triage, AI-Draft-Email, AI-Anruf-Assistent). Konkrete Pflichtliste: (1) **Chatbot-Disclosure-Banner** ("Sie interagieren mit einem KI-System") in jedem Cosmi-AI-UI-Element — muss vor Launch implementiert sein. (2) **AI-Output-Markierung**: Wenn Cosmi AI E-Mail-Drafts oder Angebotsdokumente erzeugt, müssen diese als AI-generated markiert sein (technisch: bis 2. Dezember, rechtlich: ab sofort zu deklarieren). (3) Compliance API von Anthropic (heute i18) liefert Teil der Infrastruktur dafür. Handlungsempfehlung: **EU-AI-Act Compliance Checklist als Pflicht-Gate vor erstem AI-Feature-Launch** — nicht als juristisches Dokument sondern als Feature-Checklist im Sprint. Modul-Pfad: `docs/regulation/eu-ai-act-art50-compliance-checklist.md`.

Jede Cosmi-AI-Demo oder Beta-Feature das ab heute läuft, unterliegt der Offenlegungspflicht. Das widerspricht einem "wir kümmern uns um Compliance vor dem Launch"-Ansatz, wenn AI-Features bereits in Entwicklung und Demo sind.
