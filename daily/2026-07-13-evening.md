#### Claude Code vs OpenCode — Token-Overhead-Analyse (n_sources:1, score:0.62, HN: 496)

**Quellen:**
- [systima.ai blog](https://systima.ai/blog/claude-code-vs-opencode-token-overhead) (direkt gelesen — vollständige Studie)

**Was passiert (Tiefenlesung — direkte Relevanz für diese Intel-Routine):**

Empirische Messung via HTTP-Proxy an der API-Grenze (Hash-Chain-verifiziert):

| Metrik | Claude Code | OpenCode | Faktor |
|---|---|---|---|
| Baseline-Overhead (Minimal-Task) | ~32.800 Tokens | ~6.900 Tokens | 4.7× |
| System-Prompt | ~6.500 Tokens (27 Tools) | ~2.000 Tokens (10 Tools) | 3.25× |
| Production-Config (Instruction Files + MCP) | ~311.000 Tokens (cold) | ~90.817 Tokens | 3.4× |
| 2-Subagent Fan-Out | 121.000 → 513.000 Tokens | n/a | 4.2× Multiplikator |
| Gleiche-Task Input-Tokens (unabhängige Tests) | 268.000 | 72.000 | 3.7× |

**Kritischer Unterschied:** Cache-Verhalten. OpenCode: byte-identische Prefixes über Sessions → stabile Cache-Hits. Claude Code: erzeugt unterschiedliche Request-Classes innerhalb Sessions, rewrite 37.000–86.000 Tokens mid-session → Cache-Write-Kosten (1.25×–2× Premium) fallen 5.9×–54× häufiger an als bei OpenCode.

Qualität: **Identisch** auf verifizierten Test-Suites.

**Cosmi-Implikation (direkt):**
Diese Intel-Routine läuft auf Claude Code / Claude Agent Harness. Der Token-Overhead ist real und messbar. Für Cosmi-Intel operativ: API-Boundary-Logging vor Production-Deployment empfohlen (wie im Paper vorgeschlagen). Für Cosmi-Plugin/MCP-Architektur: **Token-Effizienz muss Architektur-Kriterium sein**. Subagent-Fan-Outs kosten 4× — jeden Subagent-Aufruf als teure Operation betrachten. Die Empfehlung aus W25-Keeper (Provider-Router) bleibt: wenn lokale oder günstigere Modelle gleiche Qualität liefern, ist der Provider-Switch wirtschaftlich begründbar. Modul-Pfad: `backend/internal/ai/plugins/token-budget/`, `backend/internal/ai/mcp/schema-minimization/` (weniger Tools = weniger Overhead).
