#### UiPath Temporal-Architektur: Event-Sourcing als Workflow-Standard der 3. Generation (n_sources:1, score:0.68)

**Quellen:**
- [Diginomica: Determinism all the way down](https://diginomica.com/determinism-how-uipaths-market-engine-beneath-turn-out-same-idea) (verif.)

**Was passiert:**
UiPath-CEO Daniel Dines erklärt: Maestro (UiPath's Orchestrations-Engine) läuft auf **Temporal** (Open-Source Durable-Execution-Engine). UiPath hostet eigene Temporal-Instanz. Technischer Kern: Temporal speichert keine State-Snapshots, sondern einen Execution-Log — beim Resume wird alles von Anfang replayed, aber ohne erneute Ausführung. Analogie: Bankguthaben aus Transaktionshistorie rekonstruieren statt Snapshot-Speicherung. Determinismus (identische Inputs = identische Outputs) ist nicht-verhandelbar für den Replay-Mechanismus. Generationenmodell: 1. Gen = dokumentenzentriert (IBM Lombardi), 2. Gen = UX/DB-zentriert (ServiceNow), 3. Gen = Code-zentriert (Temporal). Schwachpunkt von UiPath's Strategie laut Diginomica: Modell-Agnostizität bietet wenig Defensibilität.

**Was bedeutet das für Cosmi?**
Technisch-architektonisches Signal. Für Cosmi's Backend: Event-Sourcing + Durable-Execution ist der Industriestandard für resiliente Workflow-Orchestrierung (Schichtplanung, Buchhaltungsabläufe, Genehmigungsprozesse). Falls Cosmi heute Prozess-Workflows mit synchronen DB-Writes implementiert, ist das technical debt gegenüber dem, was Temporal ermöglicht. Kein Sofort-Build-Impakt, aber Architektur-Awareness: `backend/internal/workflow/engine/` sollte Temporal-kompatibel designt sein oder Temporal direkt evaluieren. Lizenz: Apache 2.0, self-hostable.

Juni 2026 live): Angriffskette: (1) Malicious Repository enthält Jupyter-Notebook mit eingebettetem JavaScript + lokale Workspace-Extension in `.vscode/extensions/`. (2) JS synthetisiert Tastatureingaben via `keydown`-Events (bubbling durch VSCode Webview-Sandbox) — simuliert `Ctrl+Shift+A` (Extension-Empfehlung akzeptieren) und `Ctrl+F1` (Installation auslösen) ohne User-Interaktion. (3) Extension installiert sich mit bypassed Publisher-Trust. (4) Extension exfiltriert GitHub-Token. **Scope des gestohlenen Tokens: Vollständiger Read/Write-Zugriff auf ALLE Repos des Nutzers** — nicht auf das aktuelle Repo begrenzt. Betroffen: github.dev (Web VSCode) und Desktop VSCode. Fix heute (3. Juni): Confirmation-Dialogs beim Öffnen von Notebooks in Web-VSCode; `skipPublisherTrust`-Parameter deaktiviert. Permanent-Fix für das underlying Webview-Security-Model noch ausstehend. Kein CVE.

**Workaround (sofort):** In Chrome: URL-Bar-Icon → Cookies → On-device Site Data → github.dev-Einträge löschen. Erzwingt Re-Authentifizierung und verhindert Angriff.

**Was bedeutet das für Cosmi?**
**Dev-Team-Action erforderlich, heute.** Jeder im Cosmi-Engineering-Team, der github.dev oder Desktop-VSCode + GitHub verwendet, ist potenziell betroffen. Konkrete Schritte: (1) Alle Team-Mitglieder sollen github.dev Browser-Data löschen (Anleitung oben). (2) GitHub Fine-Grained Personal Access Tokens prüfen und rotieren — insbesondere Tokens mit Repo-Write-Zugriff. (3) GitHub Audit Log checken: `github.com/{org}/audit-log` — unbekannte Zugriffe auf private Repos seit 2. Juni 2026 als Incident-Indikator. Fix ist live, aber prüfen ob Cosmi-Dev-Team Desktop-VSCode nutzt (Desktop-Fix unklar). Modul-Pfad: keine Backend-Änderung nötig, aber `docs/security/incident-response/2026-06-03-vscode-token-rotation.md` anlegen.
