#### Anthropic: "How we contain Claude" — Sicherheitsarchitektur für LLM-Integration (n_sources:1, score:0.56) via HN

**Quellen:**
- [Anthropic Engineering Blog](https://www.anthropic.com/engineering/how-we-contain-claude) (Technischer Deep-Dive)

**Was passiert:**
Anthropic veröffentlicht detaillierte Containment-Architektur. Für Cosmi-Engineering direkt relevante Patterns:

**Isolation-Levels (nach Use Case):**

| Anwendungsfall | Isolation | Overhead |
|---|---|---|
| Multi-Tenant Server | gVisor Container + ephemeral FS | Niedrig |
| Desktop-Tools (Dev-Focus) | OS-Sandbox (Seatbelt/bubblewrap) + HITL | Mittel |
| Enterprise Non-Technical Users | Sealed VM + Hypervisor | Hoch |

**Kritische Sicherheits-Patterns für Cosmi:**
1. **Credentials-Separation:** Host-Keychain hält Credentials, VM/Container bekommt nur per-Session-Scoped-Token. Gilt direkt für Cosmi-AI-Features: Cosmi-DB-Credentials dürfen dem LLM niemals direkt zugänglich sein.
2. **Trust-Dialog-Timing:** Konfiguration (z.B. Workspace-Settings) wird erst NACH expliziter User-Bestätigung geladen — verhindert Prompt-Injection über Konfigurationsdateien.
3. **MCP-Sicherheit:** Remote-MCPs werden anders behandelt als lokale — Remote-Tools kontinuierlich evaluiert, lokale Tools wie installierte Software gesichert. Für Cosmi-Plugin-Vision: MCP-Remote-Plugins brauchen eigenes Trust-Level-System.
4. **Egress-Allowlist:** Network-Egress wird als "Capability Grant" interpretiert, nicht als Destination-Filter. Bei Cosmi-AI: welche externen Endpunkte darf ein AI-Agent erreichen?
5. **Persistent Memory als Injection-Vektor:** CLAUDE.md und Session-State können durch Angreifer manipuliert werden. Wenn Cosmi AI-Memory-Features baut (Hyper-ähnlich), muss Memory-Input sanitized werden.

**Was bedeutet das für Cosmi?**
Cosmi wird AI-Features in CRM/Helpdesk/Formulare einbauen. Bevor der erste Productionsfeature live geht: `backend/internal/ai/security/containment-policy.md` als Architekturdokument erstellen, das diese 5 Patterns verpflichtend macht. Nicht nach dem ersten Security-Incident.
