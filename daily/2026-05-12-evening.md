#### EU AI Act Art. 50 Disclosure-Deadline: 82 Tage (n_sources:1, score:0.90) `i02`

**Quellen:**
- [Heise: KI-Transparenz — EU-Kommission konkretisiert Regeln gegen digitale Täuschung](https://www.heise.de/news/KI-Transparenz-EU-Kommission-konkretisiert-Regeln-gegen-digitale-Taeuschung-11290417.html) (Leitlinien-Analyse)

**Was passiert:**
Die EU-Kommission hat finale Leitlinien zu Artikel 50 des AI Act veröffentlicht. Vier Pflicht-Kategorien ab **2. August 2026** (82 Tage):

1. **Interaktive AI-Systeme** (Chatbots, Voice Assistants): Nutzer müssen unzweideutig informiert werden, dass sie mit AI kommunizieren — explizit mit Schutzpflichten für Kinder und vulnerable Gruppen.
2. **AI-generierte Inhalte** (Text, Bilder, Video): Maschinenlesbare Markierung verpflichtend; bei Public-Interest-Inhalten zusätzlich explizite Disclosure gegenüber dem Nutzer.
3. **Biometrie & Emotionserkennung**: Strenge Informationspflichten gegenüber betroffenen Personen.
4. **Deepfakes & politische Synthetic-Inhalte**: "Klar als KI-generiert deklariert" — außer bei offensichtlicher künstlerischer/satirischer Verwendung.

**Ausnahmen:** Grammatik-Korrektur ("kein wesentlicher Eingriff"), private nicht-kommerzielle Nutzung (Weihnachtskarten). **Ausnahme der Ausnahme:** Privat erstellte politische Synthetic-Inhalte, die auf Social Platforms geteilt werden, fallen wieder unter die Pflicht.

Öffentliche Konsultation bis **3. Juni 2026** offen — Cosmi kann offiziell Feedback einreichen.

**Was bedeutet das für Cosmi?**
Jedes AI-Feature, das Cosmi heute hat oder plant, fällt ab August unter Art. 50: AI-Draft-Funktion im Helpdesk (`backend/internal/helpdesk/ai_draft/`), zukünftige CRM-AI-Triage, geplante Chatbot-Funktionen. Konkret: (1) UI-Label "Entwurf von AI erstellt" muss technisch erzwungen sein, nicht optional. (2) API-Flag `ai_generated: true` in allen relevanten Response-Typen. (3) Falls Cosmi eine Voice-Assistant-Komponente plant: Disclosure-Pflicht besteht ab erstem Wort. Empfehlung: Compliance-Checkliste als GitHub-Issue bis **3. Juni** fertig haben — gleichzeitig als Input für die EU-Konsultation nutzbar (Praxis-Feedback eines KMU-SaaS-Anbieters hat Gewicht).

### tech-trends — Supply-Chain-Security

#### 🚨 TanStack npm Supply-Chain-Angriff: Vollständige Analyse (n_sources:1, score:0.83) `i06`

**Quellen:**
- [TanStack: npm Supply-Chain Compromise Postmortem](https://tanstack.com/blog/npm-supply-chain-compromise-postmortem)

**Was passiert — Attack-Chain (Schritt für Schritt):**

1. **Entry**: Malicious Fork sendet PR mit obfuskiertem Code. Workflow `bundle-size.yml` nutzt `pull_request_target` — dieser Trigger läuft mit Repo-Owner-Permissions, nicht Fork-Permissions.
2. **Cache Poisoning**: Malicious Code schreibt speziell berechneten Key in `pnpm-store`. Der Key ist identisch mit dem Key, den der legitime `release.yml`-Workflow später berechnet und abruft. Der 1,1 GB vergiftete Cache überlebt über Trust-Boundaries hinweg.
3. **OIDC Token Extraction**: Attacker-kontrollierter Binary liest OIDC-Token aus GitHub Actions Runner Memory (`/proc/<pid>/mem`). Mit OIDC-Token kann direkt auf npm gepublisht werden — ohne npm-Credentials, ohne normale Publish-Workflow-Schritte.
4. **Publishing**: 42 `@tanstack/*` Packages, 84 malicious Versionen in **6 Minuten** (19:20:39–19:26:14 UTC, 11. Mai 2026).
5. **Payload**: Credential Harvesting — AWS IMDS/Secrets Manager, GCP Metadata, Kubernetes Service Account Tokens, Vault Tokens, `~/.npmrc`, GitHub Tokens (env vars, gh CLI, `.git-credentials`), SSH Private Keys. Exfiltration via Session Messenger (E2E-verschlüsselt, nicht mitschneidbar).

**Hauptsächlich betroffene Packages**: `@tanstack/router*` Familie. Bestätigte Clean Families: `@tanstack/query*`, `@tanstack/table*`, `@tanstack/form*`, `@tanstack/virtual*`, `@tanstack/store`, `@tanstack/start`.

**Erkennung** — Zeichen einer kompromittierten Installation:
- `optionalDependencies` enthält `"@tanstack/setup": "github:tanstack/router#79ac49eedf..."` (unbekannter Entry)
- `router_init.js` hat Größe ~2,3 MB (ungewöhnlich groß)
- Spezifischer pnpm cache key: `Linux-pnpm-store-6f9233a50def742c...`

**Remediation für Cosmi-Dev-Team — PRIORITÄT: HOCH:**
1. **Heute noch**: `package.json` und Lock-Files auf `@tanstack/*` prüfen.
2. Falls vorhanden und npm install zwischen 19:20–19:26 UTC 11. Mai lief: **Host als kompromittiert behandeln**.
3. Sofort rotieren: AWS, GCP, Kubernetes, Vault, GitHub, npm, SSH-Keys auf betroffenen Maschinen.
4. Access-Logs prüfen: Suspicious Activity nach 19:26 UTC 11. Mai.

**Prävention — sofortige GitHub Actions Härtung:**
- Alle Action-Refs auf Commit-SHAs pinnen (statt `@v6.0.2` oder `@main`)
- `pull_request_target`-Workflows auditieren: kein Schreibzugriff bei Fork-PRs
- `repository_owner`-Guard zu Workflow-Checks hinzufügen
- Cache-Scopes zwischen PR-Workflows und Production-Workflows trennen
- Internes Alerting auf npm-Package-Publishes aktivieren

**Was bedeutet das für Cosmi?**
Cosmi selbst veröffentlicht keine npm-Packages, aber Cosmi verwendet sehr wahrscheinlich npm-Abhängigkeiten im Frontend-Stack. Die Frage ist nicht "nutzt Cosmi TanStack?" sondern "welche Maschinen haben `npm install` am 11. Mai nach 19:20 UTC laufen gehabt?" Modul-Pfad: `frontend/` (npm audit), `.github/workflows/` (Actions-Härtung).

## Was widerspricht Cosmi-Strategie heute?

1. **AI-Agent-Gap ist ein strategisches Risiko, keine technische Lücke.** Die Agentic-AI-Welle (GitLab, Legora, Claude AWS — drei Signale heute) ist kein "Phase D"-Thema mehr. Cosmi hat AI als spätere Phase geplant; der Markt forciert es jetzt als Preis-Differenzierungsmechanismus. Wenn Cosmi bis Ende 2026 keine glaubwürdige AI-Agent-Story hat, verliert es nicht Features — es verliert die Upmarket-Positionierung vollständig an HubSpot/Pipedrive.

2. **Claude Platform on AWS ist NICHT EU-Compliant für Cosmi-Core-Features.** Die naheliegende AI-Infra-Entscheidung (AWS-nativer Claude = Enterprise-friendly) kollidiert mit Cosmi's eigenem USP. AWS-Claude hat keine EU-Data-Residency-Garantie. Wer AWS-Claude als Backend für Cosmi-AI-Features nutzt, bricht das Versprechen der Datensouveränität. Die Entscheidung zwischen direktem Anthropic API (Self-Hosted = EU-safe) und AWS-Claude muss explizit getroffen werden — nicht implizit durch Convenience.

3. **Legora besetzt den Vertrags-Layer mit $5.6 Mrd. — Cosmi's Phase D hat kein Zeitfenster mehr für einen eigenständigen Aufbau.** Wenn Cosmi Phase D (Verträge) als In-House-Build plant, konkurriert es mit einem bestens finanzierten, Anthropic-nativen Spezialisten. Die realistische Option: Legora (oder ähnliche EU-Legal-AI-Anbieter) als API-Integration im Cosmi-Vertrags-Modul — Cosmi liefert den Business-Context (CRM-Daten, Deal-History), Legora liefert die Vertrags-Intelligenz.

4. **Microsoft Purview zeigt, dass "Privacy-by-Claim" nicht ausreicht.** Cosmi muss "Privacy-by-Architecture" beweisbar machen — d.h. technisch verifizieren und dokumentieren, dass kein Prompt-Logging, kein Telemetrie-Upload von Nutzerinhalten, keine US-Cloud-AI-Calls aus Self-Hosted Deployments stattfinden. Sonst ist der Sovereignty-USP eine Marketingaussage ohne technischen Rückhalt.
