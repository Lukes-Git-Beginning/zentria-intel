#### Intercom: Conversation Design für AI-Agents (n_sources:1, score:0.70) — LATE-CATCH Jun 18

**Was passiert:**
"Conversation Design" ist eine neue Disziplin für AI-First-Support-Teams. Kernaussage: Benennt einen Owner, der definiert wie der Agent klingt und antwortet — nicht via Prompt-Engineering per se, sondern via fünf Dimensionen: (1) Ton/Persönlichkeit, (2) Antwort-Struktur, (3) Handoff-Logik, (4) Interaktionsfluss, (5) Antwortqualität. Praktisches Tool: Schreibe **einen Absatz** der den Soll-Klang definiert — das ist das Tone-of-Voice-Dokument. **Was bedeutet das für Cosmi?**
Feature-Spec direkt ableitbar für `backend/internal/helpdesk/ai/auto-reply/conversation-design/`: Beim Konfigurieren des Auto-Reply-Agents braucht der Cosmi-Admin ein Freitextfeld "Unser Support-Ton in einem Satz", das systemseitig als Ton-Direktive in jeden Prompt eingebaut wird. Handoff-Logik (an human Agent) muss Gesamtkonversation + Summary + Eskalationsgrund übergeben — das ist nicht optional. KPI-Vorschlag: CX-Score (nicht CSAT) als Qualitätsmetrik von Anfang an in der Analytics-Schicht (`backend/internal/analytics/ai-outcomes/`). **Quelle:**

**Was passiert:**
**AI Act Artikel 50 tritt am 2. August 2026 in Kraft** — in **11 Tagen**. Anforderungen:

| Verpflichtung | Wirksamkeit | Betroffene Systeme |
|---|---|---|
| AI-Systeme die mit Menschen interagieren müssen die Interaktion als KI kennzeichnen | 02.08.2026 (neue Systeme) | Chatbots, Auto-Reply, Triage |
| Emotion-/Biometrie-Erkennung muss offengelegt werden | 02.08.2026 | - |
| KI-generierte Inhalte (Bilder, Audio, Video) müssen Wasserzeichen + Metadaten tragen | 02.08.2026 | AI-generierte Medien |
| Text-Wasserzeichen: AUSGENOMMEN | - | (Technologie nicht reif) |
| Bestandssysteme (vor Aug 2): Übergangsfrist | bis 02.12.2026 | Existing Deployments |

Bußgelder: bis €15 Mio. oder 3% des weltweiten Jahresumsatzes.

**Was bedeutet das für Cosmi?**
Für Cosmi-AI-Features (Auto-Reply-Drafts, AI-Triage): Text-Wasserzeichen ist ausgenommen, aber **Offenlegungspflicht besteht**: Wenn Cosmi einen AI-generierten Reply-Draft zeigt, muss der User erkennen dass es KI ist. Das ist in der UX bereits klar (Draft-Label), aber Legal sollte prüfen ob es Art.-50-konform ist — z.B. durch explizites "Dieser Entwurf wurde von KI erstellt" in der UI statt nur einem Icon. **Action bis 02.08.2026**: Legal-Check Cosmi-AI-UX für alle Features die Text an Endkunden senden. **Quelle:**
- [WebRTC Hacks — Vector Vibing to Speed Up Opus Encode by 20%](https://webrtchacks.com/vector-vibing-to-speed-up-opus-encode-by-20/) (Jul 2)

**Was passiert:**
Chromium 152 aktiviert AVX2-Vektorisierung für Opus-Encoding. Drei Kernel wurden mit AVX2 kompiliert: `silk_inner_product_FLP_avx2.c`, `silk_NSQ_del_dec_avx2.c`, `celt_pitch_xcorr.c`. Die Kernel existierten seit libopus 1.5.2 (April 2024) — wurden aber durch veraltete Build-Konfiguration (Kommentar von 2018) nicht aktiviert. **Messwerte:**

| Szenario | CPU-Reduktion |
|---|---|
| Mono Speech, 64 kbps (VoIP-Standard) | **17,5%** |
| Mono Speech, 32 kbps | **22,9%** |
| Stereo Musik, 64 kbps | ~2% |
| Decode | ~1,5% (Rauschen) |

Plattform: Desktop x86/x64. Server-seitiges Encoding profitiert besonders ("20% über alle Encodes → kommt direkt von der Compute-Rechnung"). Graceful Fallback auf SSE4.1 auf Non-AVX2-Systemen.

**Was bedeutet das für Cosmi?**
Cosmi-Dialer-Stack (WebRTC, Speech-heavy VoIP) profitiert direkt von Chromium 152 im Browser-Client. Server-seitig (falls Cosmi Recording/Transcoding macht): AVX2 auf x86-64 Server aktivieren, 17-23% CPU-Einsparung auf Speech-Encoding. Bei wachsendem Dialer-Nutzer-Volumen skaliert dieser Benefit linear — potenziell signifikante Infrastrukturkosten-Reduktion. Architektur-Action: Prüfen ob Cosmi-Dialer-Recording auf x86-64 Server läuft und ob Opus 1.5.2+ verwendet wird.
